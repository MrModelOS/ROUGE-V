## Зачем это нужно

Если вы писали на CUDA — вы знаете это чувство. Код работает, всё хорошо, а потом нужно перенести его на другое железо, и начинается месяц работы. Не потому что задача сложная, а потому что выходной стандарт **закрыт**.

Стоимость этого замка — не «закрепостничество», а конкретные деньги. Из `docs/04`:

```
$/токен = (железо/срок + энергия + память + операции) / токенов за срок
```

Значительная часть цены — не кремний и не HBM, а плата за право пользоваться проприетарным софтом. Пока единственный способ её не платить — переписать всё.

**ROUGE-V делает так, чтобы этот способ перестал быть единственным.**

## Что уже работает

Не обещания, а код и зелёные тесты — **24 штуки**, прямо сейчас в `main`:

| | |
|---|---|
| **PTX → LLVM IR → нативный код** | `ptx2ir`, без эмуляции инструкций |
| **PTX от настоящего `nvcc`** | 8 из 8 сгенерированных NVIDIA ядер идут насквозь |
| **Два пути — один результат** | AOT-компиляция и интерпретатор сходятся бит-в-бит |
| **Shared memory + `bar.sync`** | блок-редукция 16×256 потоков, честная SIMT-семантика |
| **Атомики** | `atom.add` / `red.add` → `atomicrmw`, реальное гоняющееся железо |
| **FP16 / BF16** | `half` / `bfloat`, `fma`, конверсии, f16-тайл в shared |
| **Тайл GEMM 16×16** | `shA`/`shB` в shared, `bar.sync`, f16 |
| **RVV** | тот же IR собирается под `rv64gcv` |
| **MLIR-контур** | `rouge-opt --rouge-simt-access-report` — анализ SIMT-паттернов |
| **Бенчмарк** | `tools/rouge_bench.py`: **в 2,79× дешевле** за токен |

```sh
git clone https://github.com/MrModelOS/ROUGE-V.git && cd ROUGE-V
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build build
ctest --test-dir build --output-on-failure            # 16/16
ctest --test-dir software/rouge-cuda/build             #  8/8
```

## Как это устроено

```
CUDA-код → PTX → rouge-ptx → ptx2ir → LLVM IR → clang → нативный бинарник
                                            └→ rv64gcv (RISC-V + Vector)
```

Перехват идёт на уровне IR, а не «прогоном чужих инструкций». Каждая PTX-регистр становится `alloca`, CUDA-спецрегистры читаются из дескриптора запуска, `bar.sync` превращается в вызов рантайма, `.shared` — в scratchpad блока.

Неподдерживаемое — **явная ошибка с указанием инструкции**, а не тихая порча. Это принципиально: транслятор, который врёт, хуже транслятора, который отказывается.

Подробности: [docs/06](docs/06-compiler-architecture.md) · [rouge-compiler](software/rouge-compiler/README.md) · [rouge-cuda](software/rouge-cuda/README.md)

## Три принципа

**1. Открытость — не компромисс, а инструмент.**
RISC-V, LLVM, MLIR, SPIR-V, Vulkan, PyTorch, Triton. Мы не изобретаем новый закрытый стандарт — мы делаем существующие открытые быстрыми и доступными.

**2. Software-first.**
Сначала софт, который работает на чужих чипах и приносит пользу сразу. Своё железо — потом, когда про спрос уже известно. Кремний без работающего софта — это дорогая демонстрация.

**3. Честность выше красивой картинки.**
Неподдерживаемое — отказ. `cvt.sat` — отказ. f64-арифметика — отказ, пока не сделаем. Мы не ставим галочку на «умеем всё».

Подробнее: [docs/00-vision.md](docs/00-vision.md)

## Юридическая рамка

Важный момент, и мы относимся к нему серьёзно: мы **не копируем и не реверс-инжинирим** проприетарные бинарники NVIDIA. Ни `nvngx`, ни заголовков cuBLAS. Реализуется только поведение, описанное в публичной документации, — это зафиксировано в [ADR-0005](decisions/0005-cuda-compat.md) и [CONTRIBUTING.md](CONTRIBUTING.md).

## Хочешь поучаствовать?

Проект открытый, и это не дежурная фраза.

* **Первый вопрос** — самый простой: `atom.cas`, `shfl` для `f16x2`, расширение PTX-подмножества. Список — в [docs/05](docs/05-roadmap.md).
* **Проверь на своей машине**: `ctest` занимает меньше секунды.
* **Нашёл баг?** Открывай issue. Лучший баг, который мы ловили, нашёл человек, который взял настоящий PTX из `nvcc` и не поверил, что он не читается.

Особенно нужны: инженер компилятора, архитектор кремния, тот, кто знает CUDA изнутри.
