# 03. Архитектура ПО — полный открытый стек

> Документ: `docs/03-software-architecture.md` · Статус: черновик v0.1 · Владелец: архитектор ПО (TBD)
> Девиз стека: **«Ваш код работает у нас»** — сначала на чужих чипах, потом на наших.

## 1. Стратегия

Софт решает войну, а не железо. Три слоя обороны:

1. **Интерфейсы** — весь код пользователя пишется на открытых абстракциях (PyTorch, Triton, SYCL/UXL, ONNX). Меняя железо, мы не меняем код клиента.
2. **CUDA-совместимость** — устаревший/закрытый код, который не перепишут, обязан работать у нас без правок (слой-переводчик).
3. **Скорость** — мы обязаны быть быстрее CUDA на тех же kernel'ах в инференсе, иначе лозунг пустой.

**Software-first:** стек выходит в 2027 на чужих чипах (ROCm/CUDA/CPU), генерирует клиентов и сигнал; чип CRIMSON получает готовую платформу день-ноль.

## 3. Слой интерфейсов (что обещаем пользователю)

| Интерфейс | Обещание | Механизм |
|---|---|---|
| PyTorch | `训练/инференс` без изменений | Torch backend через компилятор (аналог TorchInductor); Day-0 поддержка |
| Triton | kernel'ы на Triton — нативно | Triton frontend → наш компилятор |
| SYCL / UXL | переносимый код | Полная поддержка SYCL 2020–2026, участие в UXL |
| ONNX Runtime | модели из экосистемы ONNX | ONNX Execution Provider |
| CUDA (легаси) | запуск без переписывания | CUDA-compat слой (перевод PTX/CUDA API → наш рантайм) |

## 4. Компилятор ROUGE (ядро софта)

- **База:** LLVM/MLIR (открытый, огромное комьюнити, поддержка переносимости).
- **Архитектура:** 4 уровня — CUDA/PTX Parser → MLIR Dialect Conversion (GPU/NVVM → Vector/Linalg → ROUGE Dialect) → Hardware-Aware Passes → RISC-V LLVM Backend. Подробно: [06. Компилятор](06-compiler-architecture.md), ADR-0006.
- **Фронтенды:** PTX/NVVM (наш `ptx2ir`), Triton-Dialect, SYCL, torch-граф, ONNX → общее IR.
- **Планировщик:** tiling по SRAM-гранулам, планирование доступа к HBM, слияние операций, KV-cache-специфичные пассы (weight-stationary для decode, page-attention).
- **Нижний IR → ISA ROUGE:** кодогенератор целевой для CRIMSON; **кросс-бэкенды** на NVPTX (NVIDIA), AMDGCN (AMD), host (x86/RISC-V с векторными ISA — конкуренция с CPU-инференсом).
- **Статус вехи:** `software/rouge-compiler` — `ptx2ir` транслирует PTX-подмножество в LLVM IR, clang собирает нативный объект, драйвер исполняет и проверяет (без эмуляции); тот же IR собирается для `rv64gcv`. Тесты: `ctest` в `software/rouge-compiler`.
- **Метрика качества:** на каждом ревизии компилятора — прогон канонического набора моделей (см. «Бенчмарки») с замером $/токен.

## 5. Рантайм и CUDA-совместимость

- **Потоки и события** — модель как CUDA (кривая обучения нулевая).
- **UVA + управление памятью:** аллокация, пэддинг страниц, prefetch-подсказки от железа.
- **CUDA-compat:** три пути, ADR-0005/0006:
  - *Динамический* (ZLUDA-подход): перехват CUDA API/PTX → наш рантайм. Быстро для легаси.
  - *Статический AOT* (основной перф-путь): `software/rouge-compiler` — трансляция PTX/IR в нативный код через LLVM/MLIR, без эмуляции инструкций.
  - *Fallback-интерпретатор* (`software/rouge-cuda`) — dev-инструмент и страховка для неподдерживаемых AOT-инструкций.
  - Юридическая валидация (у NVIDIA есть иски против совместимых слоёв — юристы обязательны, работаем с открытыми инструментами, не копируем код CUDA).
  - **Статус:** каркас реализован — `software/rouge-cuda` (CPU-эмуляция, PTX-подмножество, driver+runtime API, dlsym-проброс). Архитектура: ADR-0005. Тесты: `ctest` в `software/rouge-cuda`.
- **Fabric-рантайм:** коллективные операции (all-reduce, all-to-all) через Rouge Fabric/UEC; балансировка MoE между чипами.

## 6. Библиотеки (flash-степень оптимизации)

| Библиотека | Назначение | Целевые примитивы |
|---|---|---|
| `rouge-gemm` | матричные умножения | FP8/INT8/INT4/FP4, разряженные 2:4, stream-K, split-K |
| `rouge-attn` | FlashAttention-семейство | FA2/FA3, page-aware, MLA (DeepSeek-style), длинный контекст |
| `rouge-moe` | MoE-план | роутинг, expert-parallel, балансировка нагрузки |
| `rouge-comm` | коллективы | all-reduce/all-to-all по стойке, неблокирующие |
| `rouge-quant` | квантизация | FP8→INT4/FP4 калибровка, AWQ/GPTQ, на лету распаковка |
| `rouge-la` | линейная алгебра | BLAS/LAPACK-совместимые, для HPC и научных задач |

**Принцип:** каждая библиотека прозрачно открыта (лицензия Apache-2.0/MIT), бенчмарки публичны.

## 7. Инференс-стек (день-ноль)

- **vLLM и SGLang** — приоритет №1: патчим и поддерживаем upstream, чтобы ROUGE был первым-class-бэкендом без форков (урок AMD: они были форками → потом стали upstream. Мы сразу в upstream).
- **llama.cpp (GGUF)** — лёгкий локальный/edge-инференс.
- **Собственный слой «Rogue-TRT»** — low-latency сервер инференса для продакшена (объединение графа, KV-кэш-эволюция, динамические батчи) — как TensorRT-LLM, но открытый.
- **Модельный реестр «Rouge Hub»**: каталог оптимизированных моделей (fused INT4-веса, конфиги, скрипты) — одна команда `rouge run ...`.

## 8. Инструменты разработчика

- `rouge-smi` (аналог nvidia-smi): статус, память, температура, счётчики $/токен на лету.
- `rouge-prof` / `rouge nsys`-аналог: профайлер графа + аппаратных счётчиков; flamegraph по умолчанию.
- `rouge-bench`: публичный прогон канонических моделей с отчётом в Markdown/JSON (репорт в руку клиенту).
- CI-инфраструктура: GPU-ферма из **чужих и наших чипов** для регрессий.

## 9. Облако (PaaS поверх стека)

- **Rouge Cloud** — первая инкарнация: аренда наших ускорителей (и пока — чужих) + API инференса (`/v1/chat/completions`-совместимо, то есть клиент OpenAI-совместимый без изменений).
- Без серверной раскладки для клиента: playground, автоскейлинг, региональные пулы (включая регионы с эмбарго на US-чипы).
- После V1-кремния Rouge Cloud становится **флагманским покупателем собственного железа** — это снижает риск «чип без спроса».
