# 02. Архитектура железа — семейство ROUGE

> Документ: `docs/02-hardware-architecture.md` · Статус: черновик v0.1 · Владелец: архитектор кремния (TBD)
> Все цифры — `[оценка]`, фиксируются через ADR по мере проектирования.

## 1. Философия кремния

Мы не строим «ещё один GPU». Мы строим **машину экономики инференса**:

- Инференс (особенно LLM) упирается не в пиковый FP8-флопс, а в **поток данных**: вес-стационарные вычисления, узкое горлышко памяти (KV-cache, длинный контекст), малые батчи, низкая задержка decode.
- Значит архитектура оптимизируется в порядке приоритета:
  1. **$ / токен** (энергия + стоимость памяти)
  2. **TOPS/W** на FP8/INT4/FP4
  3. **Пропускная способность памяти на ватт** и на доллар
  4. Полезная матричная производительность (не пиковая)

**Кодовое имя первого чипа:** *CRIMSON* (Crimson V1). Следующий: *SCARLET* (V2). Семейства далее — по палитре ROUGE.

### 2.1 Ключевые структурные решения `[TBD → ADR]`

| Решение | Предложение | Резон |
|---|---|---|
| Компоновка | Компьютинг-чиплеты + IO-чиплет + HBM | Гибкость производства, дешёвая повторяемость (как у AMD) |
| Соединение чиплетов | UCIe 2.x (стандарт, не проприетарный) | Открытость, вторая фабрика без переделки |
| Управляющие ядра | RISC-V (RV64GC), 4–8 ядер на чип | Без лицензий ARM/NVIDIA, открытая экосистема инструментов |
| Упаковка | CoWoS-аналог / RDL-фанера у фабрики; SRAM близко к тензорному движку | Плотность, энергия на бит |
| Лицензия ISA | Наш собственный ускорительный ISA поверх RISC-V (адресация, атрибуты) | Контроль + открытость (опубликуем) |

## 3. Тензорный движок (Tensor Engine)

- **Ядро:** систолическая матрица + тензорные ядра на FP8/FP4/INT4/INT8/BF16/FP16/FP32 (FP32 — для совместимости, не для скорости).
- **Режим разреженности:** структурная разреженность 2:4 (standard в индустрии), плюс стриминг разреженности для MoE (маршрутизация экспертов — ключевая нагрузка).
- **Спецблоки:**
  - *Flash-Attention-блок*: аппаратный KV-cache-движок (страница памяти, поиск по страницам);
  - *MoE-коммутатор*: аппаратная маршрутизация токенов между экспертами без холостых циклов;
  - *Квантизатор в полёте*: INT4/FP4-копии весов в SRAM, распаковка на лету.
- **Целевые параметры CRIMSON V1 `[оценка]`:**

| Параметр | Цель V1 | Для сравнения (2026) |
|---|---|---|
| Полезные FP8 TFLOPS (dense) | 400–800 | B300 ~2.25P (пиковые), MI355X ~2.3P |
| FP8 TFLOPS/W | **лидирующий класс** (цель 2–4× от NVIDIA на $/токен) | Gaudi 3 уже был лучше H100 на инференсе — мы должны быть лучше Gaudi 3 |
| HBM | 192–256 ГБ HBM3e, → HBM4 в V2 | B300: 288 ГБ HBM3e |
| Пропускная память | 6–8 ТБ/с | B300: 8 ТБ/с |
| SRAM на чиплет | 64–128 МБ (вес-стационар) | — |
| TDP | 350–700 Вт (варианты: воздух/жидкость) | B300: до 1400 Вт (стойка) |

> **Позиционирование:** мы НЕ догоняем пиковые флопсы. Мы выигрываем на **$/токен при том же качестве** и на **TOPS/W**. Публичный бенчмарк отказа: «CRIMSON обслуживает ту же модель в 2× дешевле за токен в инференсе, чем конкурент X».

## 4. Память и кэш

- **Иерархия:** регистры тензорного ядра → SRAM-«гранулы» на чиплет (веса, KV) → HBM → хостовый/удалённый (через CXL).
- **Единое виртуальное адресное пространство** (UVA): CPU-и GPU-код видит одну память, внешняя фрагментация KV-cache решается аппаратно.
- **KV-cache-first SRAM-политика:** приоритет кэша — страницы KV, затем веса; алгоритм управления — в рантайме, но аппаратные подсказки (`prefetch_kv`, `evict_hint`).

## 5. Интерконнект

| Уровень | Решение | Почему |
|---|---|---|
| Внутри чипа (чиплет↔чиплет) | UCIe 2.x | открытый стандарт |
| Ускоритель↔ускоритель (LM на 8–16 чипов) | **Rouge Fabric** — выделенная фабрика на базе Ethernet-транспорта (UEC-совместимый), P2P DMA | масштабирование без проприетарных NVLink |
| Стойка/кластер | Ethernet 800G → 1.6T (UEC) | стандарт, много поставщиков, дешевле NVSwitch-системы |
| Хост-шина | PCIe 6.0 / CXL 3.x | совместимость |

**Стратегия:** не строим проприетарный протокол. Строим поверх открытых транспортных стандартов. Это убирает один из главных барьеров «ещё одна экосистема».

## 6. Виртуализация и мультитенантность

- SR-IOV, GPU-виртуализация, разделяемая память между виртуальными функциями.
- Аппаратные счётчики и изоляция для безопасности мультитенантности (наш облачный сервис — первый клиент).
- QoS на уровне фабрики (пропускная способность и задержка на арендатора).

## 9. Контрольные точки разработки кремния (см. также roadmap)

1. **Симулятор ISA + компилятор end-to-end** (до любых денег в кремний) — подтверждение, что софт-модель работает.
2. **FPGA-прототип** тензорного движка + памяти — проверка микроархитектуры на реальных моделях.
3. **Tapeout тестового чипа** (малый die, 1–2 чиплета) — проверка фабрики, упаковки, HBM-контроллера.
4. **Tapeout CRIMSON V1** → брингап → валидация → производство.
