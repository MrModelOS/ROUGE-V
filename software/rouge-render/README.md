# rouge-render — своя графика: path tracer, денойзер, темпоральный апскейлер

**Что это.** Волна 4 роадмапа ROUGE-V: «свой вместо OptiX/DLSS». Не шим и не
обёртка — три собственные реализации, которые вместе дают тот же эффект, что
даёт DLSS: реконструкция (пространственная) + накопление по времени +
демоизинг.

Никаких чужих библиотек: ни DLSS, ни OptiX, ни их нейросетей, ни даже
изображений-ассетов (сцена описана в коде). Измеряем качество сами: PSNR и
SSIM против сходящегося эталона того же рендера.

**Чего это НЕ делает.**

- Это **не DLSS**. У DLSS реконструкция нейросетевая: сеть обучена на данных
  NVIDIA, веса закрытые. У нас — классическая: бикубическая реконструкция с
  учётом джиттера, репроекция истории по векторам движения, variance clipping,
  проверка глубины. Это не «то же качество», зато это полностью наш код.
- Это **не трассировщик общего назначения**: сцена — Cornell box, один
  диффузный материал, один площадной источник, камера с ортографией взгляда.
  Расширение на геометрию/материалы — отдельная работа.
- Это **не GPU-код**: всё считается на CPU, в double/float. Смысл — показать
  путь целиком, а не побить чей-то FPS.

## Сборка и тесты

```bash
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -S software/rouge-render
cmake --build build
ctest --test-dir build --output-on-failure
```

Зависимость одна — `rouge-numerics` (из неё берётся наш же splitmix64, чтобы
все проекты стека давали одинаковую последовательность случайных чисел).

## Что внутри

| Файл | Что делает |
| --- | --- |
| `src/pathtrace.cpp` | Path tracer: диффузный Cornell box, next-event estimation + **MIS** (power heuristic) с BRDF-сэмплированием, косинусный отсчёт, русская рулетка, накопление по отсчётам (сумма и сумма квадратов → дисперсия оценки), G-буфер (нормаль, глубина, альбедо, мировая позиция), firefly clamp |
| `src/denoise.cpp` | Денойзер: à-trous вейвлет (ядро B-spline 5 отсчётов, шаг 1→2→4→8) с весами по нормали, **относительной** глубине и яркости, отмасштабированной ошибкой оценки; дисперсия фильтруется тем же ядром |
| `src/upsample.cpp` | Темпоральный апскейлер 2×: джиттер-осознанная реконструкция Catmull-Rom → репроекция истории по векторам движения → variance clipping по окрестности в YCoCg → проверка глубины → смешивание с коэффициентом, падающим при движении |
| `src/metrics.cpp` | PSNR и SSIM (окно 11×11, гаусс σ=1.5) по тонированному изображению |

Почему рендер сделан с MIS: чтобы эталон (тот же рендер со многими отсчётами)
был **несмещённым**. Иначе «улучшение PSNR после фильтра» могло бы быть
артефактом смещения, а не настоящим улучшением.

## Замеры (i5-1135G7, 64×64, эталон — 256 spp)

```
GT: 64x64, 256 spp, средняя яркость эталона 0.264
денойзер: PSNR шум 27.91 -> 28.79 (+0.88 дБ), SSIM 0.8729 -> 0.9266
апскейлер (статичная камера):  билинейный PSNR 21.60 (SSIM 0.6932) -> наш PSNR 25.08 (SSIM 0.8157)
апскейлер (движущаяся камера): билинейный PSNR 21.60 (SSIM 0.6933) -> наш PSNR 25.25 (SSIM 0.8259)
```

Как читать:

- **Денойзер** снимает шум с 4-отсчётного кадра: +0.88 дБ PSNR и +0.054 SSIM.
  На одном отсчёте PSNR не растёт: картинку тонят единичные яркие выбросы
  («файрфлаи»), и а-тру фильтр на них ничего не может — это честное
  ограничение метода, а не недоработка.
- **Апскейлер** даёт **+3.5…+3.7 дБ** и **+0.12 SSIM** против билинейной
  интерполяции одного кадра: накопление по времени убирает шум, а
  джиттер-осознанная реконструкция не даёт истории размазаться.
- При **движущейся камере** история перепроецируется, часть резкости теряется
  на пересемплировании, поэтому выигрыш меньше, чем при прогрессивном
  уточнении (статичная камера) — это тоже видно из таблицы.

Что здесь **не** измерено (и не обещается): работа на GPU, сравнение с
DLSS/FSR/XeSS (у нас нет ни их кода, ни их API, ни их весов), поведение при
occlusion, TAAU-фильтр с настоящей нейросетью, шум от motion blur.

## API

```c
#include "rouge/render.h"

/* Кадр: рендер + накопление. max_radiance — firefly clamp (0 = выкл). */
int rouge_render_cornell(RougeRenderTarget* t, const RougeCamera* cam, int spp,
                          int bounces, uint64_t seed, int frame, int reset,
                          float max_radiance);

/* Дисперсия оценки среднего: (E[x^2]-E[x]^2)/N. */
int rouge_render_variance(const RougeRenderTarget* t, float* variance);

/* Денойзер à-trous. */
int rouge_denoise_atrous(const RougeImage* color, const RougeGBuffer* g,
                         const float* variance, int iterations, float phi_normal,
                         float phi_depth, float phi_variance, RougeImage* out);

/* Темпоральный апскейлер 2x. */
int rouge_upsample_temporal(const RougeImage* low, const RougeGBuffer* g,
                            const float* motion, const RougeImage* history,
                            const float* history_depth, float blend,
                            float clip_gamma, float jitter_x, float jitter_y,
                            RougeImage* out, RougeImage* new_history,
                            float*new_history_depth);

/* Векторы движения по движущейся камере (чистое движение камеры). */
int rouge_motion_from_world(const RougeGBuffer* g, const RougeCamera* cam_cur,
                             const RougeCamera* cam_prev, float* motion);

/* Метрики. */
double rouge_psnr(const RougeImage* a, const RougeImage* b);
double rouge_ssim(const RougeImage* a, const RougeImage* b);
```

## Узкие места (честно)

- **CPU, без SIMD.** В ядре нет интринсиков: скалярные циклы, компилятор
  автовекторизует где может. На GPU тот же алгоритм — другая работа.
- **Реконструкция классическая, не нейросетевая.** Разница в качестве на
  сложных сценах (мелкая деталь, сильный блюр, спекулярные блики) будет
  заметна в нашу пользу у DLSS.
- **Сцена Cornell box.** Один материал, один источник. Общая геометрия,
  стекло, волосы — не поддерживаются.
- **Нет TAAU-фильтра.** Наша реконструкция не «понимает» содержимое кадра, она
  передискретизирует. На резких краях и в движении это видно.
- **Clip-коридор variance clipping** — эвристика: при сильной дисперсии
  шумного кадра коридор широкий, при гладком — узкий; подбор `clip_gamma` —
  это ручной параметр, а не обученная сеть.
- **Нет учёта цвета/экспозиции в клиппинге** по YCoCg: клиппим покомпонентно,
  без учёта яркости сцены.

## Clean-room

Сцена, алгоритмы и код написаны здесь, с нуля, по опубликованным описаниям
методов (à-trous/SVGF, variance clipping, TAA-репроекция, MIS). Никакой код,
бинарники, ассеты и документация NVIDIA (DLSS, OptiX) не использовались и не
разбирались. PTX-сторона проекта (интерпретатор, AOT-нижнинг) — отдельная
часть ROUGE-V со своими правилами clean-room.
